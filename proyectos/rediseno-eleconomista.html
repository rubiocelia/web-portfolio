Rediseño de elEconomista.es: de Bootstrap a una rejilla propia

Estamos rediseñando la web entera del periódico para modernizarla. Una de las piezas clave ha sido sustituir Bootstrap por un sistema de rejilla propio, programado desde cero con CSS Grid, pensado para cargar menos y mejorar las Core Web Vitals.

Rol
Diseño en Figma y desarrollo frontend
Equipo
Dos personas, en coordinación con Redacción y Desarrollo
Herramientas
Figma, HTML, CSS Grid, variables CSS, JavaScript
Fecha
2026, lanzamiento por fases

El punto de partida

Toda la maquetación de la web dependía de Bootstrap. Funcionaba, pero cargaba muchas reglas que no se usaban y obligaba a pensar cada bloque dentro de las columnas del framework.

Como el rediseño aún no está publicado del todo, aquí no hay capturas: el esquema de arriba explica el sistema con bloques genéricos.

Cómo lo hicimos

  • Varias propuestas de la web entera en Figma.
  • Ideas de diseño por módulos y secciones, para verlas en conjunto y quedarnos con las mejores.
  • Reuniones con Redacción: el rediseño también actualiza el gestor desde el que preparan las portadas, para que trabajen más rápido.
  • Reuniones con Desarrollo para acordar cómo trabajar juntos.
  • Maquetas programadas que Desarrollo recibe y termina de integrar.
  • Maquetas en producción para que cada departamento haga pruebas y pida correcciones.

Una rejilla propia

Bootstrap deja paso a una rejilla propia con CSS Grid, basada en la clase .gd: 12 columnas en escritorio, 6 en tablet y 1 en móvil. Las rejillas se anidan, así que la portada, cada bloque de noticias y el contenido de cada noticia usan el mismo sistema y quedan alineados sin clases extra.

El motivo es la libertad de diseño: en un periódico, cada noticia puede necesitar un tamaño distinto según su importancia, y las columnas fijas de un framework se quedaban cortas. Además, la web ya no carga ninguna hoja de estilos de Bootstrap.

Este es un fragmento simplificado de la rejilla. La clase .gd crea la rejilla, y cada bloque dice cuántas columnas ocupa en escritorio (.gd-8) y en tablet (.gd-md-6): 

/* Rejilla base: 12 columnas */
.gd {
  display: grid;
  grid-template-columns: repeat(12, 1fr);
  grid-column-gap: 1.875rem;
}

/* Cuántas columnas ocupa cada bloque */
.gd-4 { grid-column: span 4; }
.gd-8 { grid-column: span 8; }

/* Tablet: 6 columnas */
@media screen and (max-width: 992px) {
  .gd { grid-template-columns: repeat(6, 1fr); }
  .gd-md-6 { grid-column: span 6; }
}

/* Móvil: una sola columna */
@media screen and (max-width: 768px) {
  .gd { grid-template-columns: 1fr; }
}

Y así se usa en el HTML:

<div class="gd">
  <section class="gd-8 gd-md-6">Noticias de sección</section>
  <aside class="gd-4 gd-md-6">Opinión</aside>
</div>

Las clases siguen la misma lógica que las de Bootstrap (.gd-8 como .col-8, .gd-md-6 como .col-md-6), así que el cambio de un sistema a otro es sencillo para todo el equipo. En móvil todo pasa a una columna, salvo la cabecera y la barra lateral, que mantienen su propia rejilla.

Colores y tipografías en variables

Los colores y las tipografías viven en variables CSS. Cada sección del periódico tiene su color, y cambiarlo es cambiar un solo valor.

  • elEconomista#ff6600
  • Hover#e05500
  • Informalia#809a17
  • Evasión#dd3333
  • Eventos#4477ee
  • Texto#242424

Los titulares usan Georgia y el texto Roboto, con alternativas de sistema. Son fuentes que ya están en la mayoría de dispositivos, así que la página no espera a descargar tipografías antes de mostrarse.

Pensado para las Core Web Vitals

Google mide la experiencia de una web con tres métricas, las Core Web Vitals. Cada decisión del rediseño ayuda a alguna de ellas:

Métrica Qué mide Qué decisiones la mejoran
LCP Cuánto tarda en verse el contenido principal Sin la hoja de estilos de Bootstrap, menos CSS que descargar; tipografías de sistema que no hay que esperar; las imágenes de más abajo se cargan solo al acercarse a la pantalla
CLS Si la página da saltos mientras carga Cada bloque tiene su sitio reservado en la rejilla, y las imágenes llevan su tamaño, así que nada empuja al resto al aparecer
INP Cuánto tarda en responder al tocar o hacer clic La maquetación es CSS puro: no hace falta JavaScript para colocar ni redimensionar bloques, y el navegador tiene menos trabajo

Lanzamiento por fases

El rediseño se publica poco a poco: primero las noticias, después las portadas y más adelante el resto de la web, como las portadillas de cada sección.
